# N3 score (mapping version 3)

All operations below use unsigned 64-bit arithmetic modulo `2^64`.

```text
k = key + 0x9e3779b97f4a7c15
k ^= k >> 32
k *= 0xbf58476d1ce4e5b9
k ^= k >> 27

x = k XOR node
x = x XOR ROTL(x, 17) XOR ROTL(x, 43)
x *= 0x2cb0f69f4abea221
x ^= x >> 27
x = ROTL(x, 23)
x *= 0xb19e04cb9dce3147
x ^= x >> 31
x *= 0xbf58476d1ce4e5b9
score = x XOR (x >> 33)
```

The owner is the node with the largest unsigned score. For each fixed key,
node-to-score is a permutation: XOR with a constant, odd multiplication,
rotation and right xorshift are invertible. The linear transform
`T(x) = x XOR ROTL(x,17) XOR ROTL(x,43)` is also invertible. Over GF(2),
`T^64` is the identity because its three rotation terms each become the
identity after six squarings. Thus `T^-1 = T^63`. The implementation
uses six squaring steps to invert it.

For rings with more than 16 nodes, construction stores `T(node)` for each
node. At lookup it computes `T(k)` once; linearity gives
`T(k XOR node) = T(k) XOR T(node)`. The optimized amd64 owner scan returns the
winning transformed ID, which is inverted once. This is exactly the same
mapping as the reference score above. The ring retains raw IDs for `Nodes`,
so large rings use an additional eight bytes per node for transformed IDs.

The permutation property prevents score ties. It does not prove unbiased
ownership for every possible node set or key stream. Finite distribution and
speed measurements are kept in the [research archive](../archive/README.md).
Version 3 remaps keys relative to versions 1 and 2; cluster participants must
agree on the version before sharing ownership responsibilities.
